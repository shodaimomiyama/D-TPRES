# サブタスクメッセージテンプレート

このテンプレートは、オーケストレータがD-TPRES暗号システムのサブタスクを作成する際に使用するメッセージの構造を定義します。

## 基本構造

```
# [サブタスク名]

## 親タスクの概要
[親タスクの簡潔な説明]

## 関連するライフサイクル
[Process/Secret/Accessライフサイクルのうち、このサブタスクが関連するライフサイクルと段階]

## 対象プロセスロール
[Owner/Holder/Requesterのうち、このサブタスクが対象とするロール]

## このサブタスクの目的
[このサブタスクが達成すべき具体的な目標]

## 詳細要件
- [要件1]
- [要件2]
- ...

## セキュリティ要件
- [ ] 秘密鍵/秘密情報が適切に保護されている
- [ ] メモリ上の秘密情報が使用後にクリアされる
- [ ] 暗号パラメータが適切に検証される
- [ ] エラー時に秘密情報が漏洩しない
- [ ] プロセスロール権限が適切に制限されている

## AOステートレス制約
- [ ] メッセージ間でのメモリ非永続性に対応
- [ ] 状態の明示的な保存・復元が実装されている
- [ ] Compute Units分散を考慮した実装
- [ ] 同期処理での実装が完了している

## 実装方針
1. [ステップ1]
2. [ステップ2]
3. ...

## テスト要件
- [ ] 暗号アルゴリズムの正確性テスト
- [ ] エラーケースのハンドリングテスト
- [ ] WASM環境での動作確認（必要な場合）

## 重要な注意事項
- 実装前に必ず `make check` を実行し、コンパイルエラーがないことを確認してください
- テストを実行する前に必ず `make lint` を実行し、リントエラーがある場合は修正してください
- 暗号ライブラリ（umbral-pre）のAPIドキュメントを参照してください
- 実装が困難な場合は、問題を明確に説明し、実装を中止してください

## コンテキスト継続情報（コンテキストリセット時用）
- 完了したステップ: [完了したステップのリスト]
- 未完了のステップ: [残りのステップのリスト]  
- 重要な状態情報: [次のサブタスクに引き継ぐべき情報]
```

## 使用例1: Umbral暗号操作の実装

```
# Umbral鍵生成とkFrag生成機能を実装する

## 親タスクの概要
D-TPRESシステムのプロキシ再暗号化機能を実装するため、Umbral暗号ライブラリを使用した基本操作を構築します。

## 関連するライフサイクル
Secret Lifecycle (作成 → 分割 → 配布)、Process Lifecycle (アクティブ段階)

## 対象プロセスロール
Owner-Process (主要)、Holder-Process (kFrag受信)

## このサブタスクの目的
Umbral暗号ライブラリを使用して、鍵ペアの生成、kFrag（鍵フラグメント）の生成、およびシリアライズ機能を実装します。

## 詳細要件
- SecretKeyとPublicKeyのペアを生成する機能を実装する
- 再暗号化鍵（kFrag）を生成する機能を実装する
- 生成した鍵とkFragをシリアライズ/デシリアライズする機能を実装する
- エラーハンドリングを適切に実装する

## セキュリティ要件
- [x] 秘密鍵/秘密情報が適切に保護されている
- [x] メモリ上の秘密情報が使用後にクリアされる
- [ ] 暗号パラメータが適切に検証される
- [ ] エラー時に秘密情報が漏洩しない

## 実装方針
1. Core ServicesのCryptoServiceを確認・拡張する
2. Owner Handlersで鍵ペア生成機能を実装する
3. kFrag生成をDistributionWorkflowに統合する
4. Domain EntitiesのProcessEntity/ShareEntityに暗号情報を追加する
5. ArweaveRepositoryImplでの永続化を実装する
6. AOステートレス制約に対応した状態管理を実装する

## AOステートレス制約への対応
- メッセージ処理後の状態保存をRepository経由で実装
- 鍵情報の安全な永続化とロード機能
- Compute Units間での状態復元の確実性

## テスト要件
- [x] 鍵ペア生成の正確性テスト
- [ ] kFrag生成の閾値パラメータ検証テスト
- [ ] シリアライズ/デシリアライズの往復テスト
- [ ] 不正な入力に対するエラーハンドリングテスト

## 重要な注意事項
- 実装前に必ず `make check` を実行し、コンパイルエラーがないことを確認してください
- テストを実行する前に必ず `make lint` を実行し、リントエラーがある場合は修正してください
- umbral-pre crateのバージョン0.11.0のAPIを使用してください
- 秘密鍵を扱う際は必ずZeroizeトレイトを使用してメモリをクリアしてください

## コンテキスト継続情報（コンテキストリセット時用）
- 完了したステップ: [1, 2]
- 未完了のステップ: [3, 4, 5]
- 重要な状態情報: generate_keypair関数は実装済み、次はkFrag生成に取り組む
```

## 使用例2: Owner UseCase Handlerの実装

```
# Owner-ProcessのUseCase Handlerを実装する

## 親タスクの概要
D-TPRESシステムのOwner-Process (P^O)がAOネットワーク上でメッセージを受信し、Controller Components経由でWorkflow Servicesとの統合を実現するハンドラーを実装します。

## 関連するライフサイクル
Process Lifecycle (初期化 → ロール設定 → アクティブ)、Secret Lifecycle (作成 → 分割 → 配布)

## 対象プロセスロール
Owner-Process (P^O)

## このサブタスクの目的
AOネットワークからのメッセージを受信し、メッセージタイプに応じて適切なハンドラー関数にルーティングする機能を実装します。

## 詳細要件
- AOメッセージのパース機能を実装する
- メッセージタイプ（Init、Split、Query等）の判定ロジックを実装する
- 各メッセージタイプに対応するハンドラー関数へのルーティングを実装する
- エラーレスポンスの生成機能を実装する

## セキュリティ要件
- [ ] メッセージの送信者認証を実装する
- [ ] 不正なメッセージフォーマットを適切に拒否する
- [ ] レート制限を考慮する
- [ ] エラーメッセージに秘密情報を含めない

## 実装方針
1. UseCase Owner Handlersの基本構造を実装する
2. MessageHandlerとの連携インターフェースを定義する
3. MessageRouterでのメッセージタイプ分岐を実装する
4. DistributionWorkflowとの統合ポイントを実装する
5. Repository経由でのプロセス状態永続化を実装する
6. AOステートレス制約に対応したエラーハンドリングを実装する

## AOステートレス制約への対応
- メッセージ処理前の状態復元機能
- 処理完了後の状態永続化機能
- Compute Units分散を考慮したステートレス設計

## テスト要件
- [ ] 各メッセージタイプのパーステスト
- [ ] ルーティングロジックのテスト
- [ ] 不正なメッセージに対するエラーハンドリングテスト
- [ ] WASM環境でのメッセージ処理テスト

## 重要な注意事項
- 実装前に必ず `make check` を実行し、コンパイルエラーがないことを確認してください
- AOネットワークのメッセージフォーマット仕様を確認してください
- WASMターゲットでのビルドを考慮し、std機能に依存しないようにしてください
- メッセージハンドリングは非同期にならないよう注意してください（AOの制約）

## コンテキスト継続情報（コンテキストリセット時用）
- 完了したステップ: []
- 未完了のステップ: [1, 2, 3, 4, 5]
- 重要な状態情報: 新規実装のため、最初からスタート
```
