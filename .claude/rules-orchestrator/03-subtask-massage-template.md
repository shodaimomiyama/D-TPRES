# サブタスクメッセージテンプレート

このテンプレートは、オーケストレータがD-TPRES暗号システムのサブタスクを作成する際に使用するメッセージの構造を定義します。

## 基本構造

```
# [サブタスク名]

## 親タスクの概要
[親タスクの簡潔な説明]

## 関連する暗号フェーズ
[Phase 0-5のうち、このサブタスクが関連するフェーズ]

## このサブタスクの目的
[このサブタスクが達成すべき具体的な目標]

## 詳細要件
- [要件1]
- [要件2]
- ...

## セキュリティ要件
- [ ] 秘密鍵/秘密情報が適切に保護されている
- [ ] メモリ上の秘密情報が使用後にクリアされる
- [ ] 暗号パラメータが適切に検証される
- [ ] エラー時に秘密情報が漏洩しない

## 実装方針
1. [ステップ1]
2. [ステップ2]
3. ...

## テスト要件
- [ ] 暗号アルゴリズムの正確性テスト
- [ ] エラーケースのハンドリングテスト
- [ ] WASM環境での動作確認（必要な場合）

## 重要な注意事項
- 実装前に必ず `make check` を実行し、コンパイルエラーがないことを確認してください
- テストを実行する前に必ず `make lint` を実行し、リントエラーがある場合は修正してください
- 暗号ライブラリ（umbral-pre）のAPIドキュメントを参照してください
- 実装が困難な場合は、問題を明確に説明し、実装を中止してください

## コンテキスト継続情報（コンテキストリセット時用）
- 完了したステップ: [完了したステップのリスト]
- 未完了のステップ: [残りのステップのリスト]  
- 重要な状態情報: [次のサブタスクに引き継ぐべき情報]
```

## 使用例1: Umbral暗号操作の実装

```
# Umbral鍵生成とkFrag生成機能を実装する

## 親タスクの概要
D-TPRESシステムのプロキシ再暗号化機能を実装するため、Umbral暗号ライブラリを使用した基本操作を構築します。

## 関連する暗号フェーズ
Phase 3: 再暗号化鍵の断片化、Phase 4: k-of-nプロキシ再暗号化

## このサブタスクの目的
Umbral暗号ライブラリを使用して、鍵ペアの生成、kFrag（鍵フラグメント）の生成、およびシリアライズ機能を実装します。

## 詳細要件
- SecretKeyとPublicKeyのペアを生成する機能を実装する
- 再暗号化鍵（kFrag）を生成する機能を実装する
- 生成した鍵とkFragをシリアライズ/デシリアライズする機能を実装する
- エラーハンドリングを適切に実装する

## セキュリティ要件
- [x] 秘密鍵/秘密情報が適切に保護されている
- [x] メモリ上の秘密情報が使用後にクリアされる
- [ ] 暗号パラメータが適切に検証される
- [ ] エラー時に秘密情報が漏洩しない

## 実装方針
1. `src/crypto/umbral.rs` ファイルを開く
2. `generate_keypair()` 関数を実装し、SecretKey/PublicKeyペアを生成する
3. `generate_kfrags()` 関数を実装し、閾値パラメータに基づいてkFragを生成する
4. シリアライズ用のトレイトを実装する
5. 各機能の単体テストを追加する

## テスト要件
- [x] 鍵ペア生成の正確性テスト
- [ ] kFrag生成の閾値パラメータ検証テスト
- [ ] シリアライズ/デシリアライズの往復テスト
- [ ] 不正な入力に対するエラーハンドリングテスト

## 重要な注意事項
- 実装前に必ず `make check` を実行し、コンパイルエラーがないことを確認してください
- テストを実行する前に必ず `make lint` を実行し、リントエラーがある場合は修正してください
- umbral-pre crateのバージョン0.11.0のAPIを使用してください
- 秘密鍵を扱う際は必ずZeroizeトレイトを使用してメモリをクリアしてください

## コンテキスト継続情報（コンテキストリセット時用）
- 完了したステップ: [1, 2]
- 未完了のステップ: [3, 4, 5]
- 重要な状態情報: generate_keypair関数は実装済み、次はkFrag生成に取り組む
```

## 使用例2: AOメッセージハンドラーの実装

```
# Owner-ProcessのAOメッセージルーティングを実装する

## 親タスクの概要
D-TPRESシステムのOwner-Process (P^O)がAOネットワーク上でメッセージを受信し、適切に処理するためのハンドラーを実装します。

## 関連する暗号フェーズ
Phase 0: プロセス生成と鍵準備、Phase 1: 秘密分割とArweave保存

## このサブタスクの目的
AOネットワークからのメッセージを受信し、メッセージタイプに応じて適切なハンドラー関数にルーティングする機能を実装します。

## 詳細要件
- AOメッセージのパース機能を実装する
- メッセージタイプ（Init、Split、Query等）の判定ロジックを実装する
- 各メッセージタイプに対応するハンドラー関数へのルーティングを実装する
- エラーレスポンスの生成機能を実装する

## セキュリティ要件
- [ ] メッセージの送信者認証を実装する
- [ ] 不正なメッセージフォーマットを適切に拒否する
- [ ] レート制限を考慮する
- [ ] エラーメッセージに秘密情報を含めない

## 実装方針
1. `src/service/ao_handler.rs` ファイルを作成する
2. `AOMessage` 構造体を定義し、メッセージのパース機能を実装する
3. `route_message()` 関数を実装し、メッセージタイプによる分岐を作成する
4. 各ハンドラー関数のスタブを作成する
5. エラーハンドリングとレスポンス生成を実装する

## テスト要件
- [ ] 各メッセージタイプのパーステスト
- [ ] ルーティングロジックのテスト
- [ ] 不正なメッセージに対するエラーハンドリングテスト
- [ ] WASM環境でのメッセージ処理テスト

## 重要な注意事項
- 実装前に必ず `make check` を実行し、コンパイルエラーがないことを確認してください
- AOネットワークのメッセージフォーマット仕様を確認してください
- WASMターゲットでのビルドを考慮し、std機能に依存しないようにしてください
- メッセージハンドリングは非同期にならないよう注意してください（AOの制約）

## コンテキスト継続情報（コンテキストリセット時用）
- 完了したステップ: []
- 未完了のステップ: [1, 2, 3, 4, 5]
- 重要な状態情報: 新規実装のため、最初からスタート
```
